## Metastore

Der **Metastore** ist das oberste sicherbare Objekt in Unity Catalog. Ein Metastore enthält alle in Unity Catalog registrierten sicherbaren Objekte einer einzelnen Cloud-Region. Dazu gehören nicht nur die Kataloge, die deine Daten organisieren, sondern auch Objekte, die steuern, wie Daten zugegriffen und geteilt werden — etwa Service Credentials, Storage Credentials, External Locations, Connections, Shares, Recipients, Providers und Clean Rooms.

Die folgende Tabelle fasst wichtige Details zum Metastore zusammen:

| Detail | Beschreibung |
| :------------------- | :----------------------------------------------------------- |
| Geltungsbereich | Ein Metastore ist auf eine einzelne Cloud-Region beschränkt. Deine Organisation benötigt einen Metastore pro Region, in der sie tätig ist. Ein einzelner Metastore kann mit mehreren Workspaces in derselben Region verbunden werden. Berechtigungsvergaben in einem Metastore gelten für alle mit diesem Metastore verbundenen Workspaces. Mit anderen Worten: Ein in einem Workspace vergebenes Privileg wirkt in allen anderen Workspaces, die sich diesen Metastore teilen. |
| Metastore-Privilegien | Privilegien auf dem Metastore erlauben Operationen auf Metastore-Ebene. `CREATE CATALOG` erlaubt es einem Nutzer beispielsweise, einen Katalog innerhalb des Metastores anzulegen. Das gewährt dem Nutzer jedoch keinen Zugriff auf Daten innerhalb des Katalogs. Die vollständige Liste anwendbarer Privilegien findet sich in der [Privilegientyp-Tabelle](https://docs.databricks.com/aws/en/data-governance/unity-catalog/access-control/privileges-reference#privilege-types). Wichtig: Auf Metastore-Ebene vergebene Privilegien vererben sich **nicht** an untergeordnete Objekte in der Hierarchie. Metastore-Level-Grants gelten ausschließlich für Operationen auf Metastore-Ebene. Das unterscheidet sich vom Vererbungsverhalten bei Katalog- und Schema-Grants, wo vererbte Privilegien automatisch für alle aktuellen und künftigen untergeordneten Objekte gelten. Siehe [Privilegienvererbung](https://docs.databricks.com/aws/en/data-governance/unity-catalog/access-control/permissions-concepts#inheritance). |
| Metastore-Admins | Der Metastore-Admin ist eine optionale Rolle in Databricks, die von Account-Admins vergeben wird. Bestimmte Fähigkeiten stehen nur Metastore-Admins zur Verfügung, darunter das Löschen des Metastores, die Verwaltung von Workspace-Zuweisungen und die Übernahme der Eigentümerschaft an jedem Objekt im Metastore — was indirekten Zugriff auf alle Daten im Metastore gewährt. Diese Fähigkeiten lassen sich nicht über reguläre Privilegienvergaben erteilen. Siehe [Metastore-Admins](https://docs.databricks.com/aws/en/data-governance/unity-catalog/manage-privileges/admin-privileges#metastore-admins). Wird ein Workspace automatisch für Unity Catalog aktiviert, erhalten Workspace-Admins eine Standard-Menge an Metastore-Level-Privilegien, darunter `CREATE CATALOG`, `CREATE STORAGE CREDENTIAL` und `CREATE EXTERNAL LOCATION`. Diese übertragen sich nicht auf andere, mit demselben Metastore verbundene Workspaces. Siehe [Workspace-Admin-Privilegien bei automatischer Unity-Catalog-Aktivierung](https://docs.databricks.com/aws/en/data-governance/unity-catalog/manage-privileges/admin-privileges#workspace-admins-auto). |

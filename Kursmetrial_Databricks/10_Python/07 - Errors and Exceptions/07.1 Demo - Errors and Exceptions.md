# Demo – Fehler und Exceptions

## Überblick

Python-Programme können auf zwei unterschiedliche Arten scheitern: durch **Syntaxfehler**, die auftreten, wenn Code falsch geschrieben ist und nicht interpretiert werden kann, und durch **Exceptions**, die zur Laufzeit auftreten, wenn Python den Code versteht, aber während der Ausführung auf ein Problem stößt. Diese Demonstration erkundet beide Fehlerarten und führt die Werkzeuge ein, die Python bietet, um Exceptions kontrolliert zu behandeln – einschließlich `try`/`except`-Blöcken, `else`- und `finally`-Anweisungen sowie `assert`-Anweisungen.

## Lernziele

Am Ende dieser Demonstration können Sie:

1. **Zwischen Syntaxfehlern und Exceptions unterscheiden** und erklären, wann jeder auftritt
2. **`try`/`except`-Blöcke verwenden**, um Exceptions zu behandeln und Programmabstürze zu verhindern
3. **Bestimmte Exception-Typen** wie `ZeroDivisionError` und `NameError` in Exception-Handlern gezielt ansprechen
4. **Mehrere Exceptions** innerhalb einer einzigen `except`-Klausel behandeln
5. **`else`- und `finally`-Anweisungen verwenden**, um die Codeausführung nach der Exception-Behandlung zu steuern
6. **`assert`-Anweisungen verwenden**, um `AssertionError`-Exceptions zur Validierung auszulösen

## A. Syntaxfehler

### A1. Was ist ein Syntaxfehler?

In Python gibt es zwei Hauptkategorien von Fehlern: **Syntaxfehler** und **Exceptions**. Ein Syntaxfehler tritt auf, wenn Code so geschrieben ist, dass Python ihn nicht interpretieren kann – der Code verletzt die Regeln der Sprache selbst, sodass Python nicht einmal versuchen kann, ihn auszuführen.

Das auskommentierte Beispiel unten veranschaulicht einen Syntaxfehler. Die Auskommentierung zu entfernen würde dazu führen, dass Python sofort scheitert, bevor irgendein Code ausgeführt wird.

```python
# if print("Hello World") # Das ist kein korrekter Python-Code, daher wird ein Syntax Error ausgelöst
```

## B. Exceptions

### B1. Was ist eine Exception?

Wenn Python den Code parsen und verstehen kann, aber während der Ausführung auf ein Problem stößt, wird der resultierende Fehler **Exception** genannt. Anders als Syntaxfehler treten Exceptions zur Laufzeit auf – Python hat verstanden, was Sie versucht haben zu tun, aber während der Ausführung ging etwas schief.

Das auskommentierte Beispiel unten löst einen `ZeroDivisionError` aus, einen von Pythons eingebauten Exception-Typen. Die Auskommentierung zu entfernen löst diese Exception aus.

```python
# 1 / 0
```

### B2. Eingebaute Exception-Typen

Python bietet einen reichhaltigen Satz eingebauter Exceptions, jede weist auf eine bestimmte Kategorie von Problemen hin. Der oben gesehene `ZeroDivisionError` signalisiert einen Versuch, durch null zu teilen.

Hier sind einige der häufigsten Exceptions für Programmieranfänger:

* **`SyntaxError`** — Wird ausgelöst, wenn Code Pythons Grammatikregeln verletzt (z. B. fehlender Doppelpunkt, nicht geschlossene Klammern)
* **`NameError`** — Wird ausgelöst, wenn eine Variable oder Funktion referenziert wird, die nicht definiert wurde
* **`TypeError`** — Wird ausgelöst, wenn eine Operation auf ein Objekt eines unpassenden Typs angewendet wird (z. B. `"hello" + 5`)
* **`ValueError`** — Wird ausgelöst, wenn eine Operation ein Argument des richtigen Typs, aber mit unpassendem Wert erhält (z. B. `int("abc")`)
* **`IndexError`** — Wird ausgelöst, wenn auf einen Listen- oder Tupel-Index zugegriffen wird, der nicht existiert
* **`KeyError`** — Wird ausgelöst, wenn auf einen Dictionary-Schlüssel zugegriffen wird, der nicht existiert
* **`ZeroDivisionError`** — Wird ausgelöst, wenn durch null geteilt wird

> **Pythons eingebaute Exceptions**
>
> Eine vollständige Liste von Pythons eingebauten Exceptions ist in der [offiziellen Python-Dokumentation](https://docs.python.org/3/library/exceptions.html#bltin-exceptions) verfügbar.

## C. Exception-Behandlung

### C1. Die `try`/`except`-Anweisung

Syntaxfehler führen immer dazu, dass ein Programm beendet wird, aber **Exceptions können behandelt werden**. Pythons `try`/`except`-Anweisung lässt Sie definieren, was passieren soll, wenn eine Exception ausgelöst wird, statt zuzulassen, dass das Programm abstürzt.

Die grundlegende Struktur lautet:

```python
try:
    # Code, der eine Exception auslösen kann
except:
    # Code, der ausgeführt wird, wenn eine beliebige Exception auftritt
```

Wenn Python einen `try`-Block betritt und auf eine Exception stößt, springt es sofort zum `except`-Block, statt mit einem Fehler zu beenden. Der Code unten demonstriert das – die Division durch null löst einen `ZeroDivisionError` aus, der abgefangen und kontrolliert behandelt wird.

```python
try:
    1/0 # Throws an exception
except:
    print("Exception Handled")
```

### C2. Einen bestimmten Exception-Typ behandeln

Die breite `except`-Klausel oben fängt jede Exception. Für präzisere Kontrolle können Sie den Exception-Typ angeben, den Sie behandeln möchten, indem Sie ihn nach dem Schlüsselwort `except` benennen:

```python
try:
    # Code, der eine Exception auslösen kann
except ExceptionName:
    # Code, der nur ausgeführt wird, wenn ExceptionName ausgelöst wird
```

Im ersten Beispiel unten wird ein `ZeroDivisionError` ausgelöst und vom Handler abgeglichen. Im zweiten (auskommentierten) Beispiel wird stattdessen ein `NameError` ausgelöst – weil der Handler nur `ZeroDivisionError` anspricht, bliebe die Exception unbehandelt.

```python
try:
    1/0 # Throws a ZeroDivisionError exception
except ZeroDivisionError:
    print("Exception Handled")
```

```python
# try:
#     print(undefined_variable) # Throws a NameError exception
# except ZeroDivisionError:
#     print("Exception Handled")
```

#### C2.1. Mehrere Exception-Typen behandeln

Um mehr als einen bestimmten Exception-Typ in einer einzigen `except`-Klausel zu behandeln, listen Sie die Exception-Namen als Tupel innerhalb von Klammern auf:

```python
except (ExceptionType1, ExceptionType2):
    # handles either exception
```

Im Beispiel unten werden sowohl ein `ZeroDivisionError` als auch ein `NameError` von derselben Klausel behandelt. Versuchen Sie, jeweils eine der Exception-auslösenden Zeilen auszukommentieren, um zu beobachten, dass beide Exceptions abgefangen und behandelt werden.

```python
try:
    1/0 # Throws a ZeroDivisionError exception
    print(undefined_variable) # Throws a NameError exception
except (ZeroDivisionError, NameError):
    print("Exception Handled")
```

#### C2.2 Den Exception-Fehler ausgeben

Den Exception-Fehler auszugeben hilft Ihnen zu verstehen, was genau schiefgegangen ist, und macht Debugging und Fehlersuche einfacher.

Versuchen Sie, jeweils eine der Exception-auslösenden Zeilen auszukommentieren, um zu beobachten, welcher Fehler ausgegeben wird.

```python
try:
    #1/0 # Throws a ZeroDivisionError exception
    #print(undefined_variable) # Throws a NameError exception
except (ZeroDivisionError, NameError) as e: print(f"Exception Handled: {e}")
```

### C3. Die `else`-Klausel

Sie können einen `else`-Block nach `except` hinzufügen, um Code zu definieren, der **nur läuft, wenn keine Exception** innerhalb des `try`-Blocks ausgelöst wurde:

```python
try:
    # Code, der eine Exception auslösen kann
except ExceptionType:
    # läuft, wenn eine Exception auftritt
else:
    # läuft nur, wenn KEINE Exception auftritt
```

Das ist nützlich, um die „Happy Path"-Logik von der Fehlerbehandlung zu trennen. Im Beispiel unten gelingt die Division, sodass der `else`-Block ausgeführt wird und das Ergebnis ausgibt.

```python
try:
    result = 10 / 2
except ZeroDivisionError:
    print("Cannot divide by zero!")
else:
    print(f"Division successful! Result: {result}")
```

### C4. Die `finally`-Klausel

Der `finally`-Block läuft **unabhängig davon, ob eine Exception aufgetreten ist oder nicht**. Er wird typischerweise für Aufräumaktionen verwendet – wie das Schließen von Dateien oder das Freigeben von Ressourcen –, die auf jeden Fall passieren müssen:

```python
try:
    # Code, der eine Exception auslösen kann
except ExceptionType:
    # läuft, wenn eine Exception auftritt
finally:
    # läuft IMMER, ob Exception oder nicht
```

Im Beispiel unten gibt der `finally`-Block eine Meldung aus, egal ob die Division gelingt oder scheitert. Versuchen Sie, den Divisor auf `0` zu ändern, um zu beobachten, dass der `finally`-Block immer noch ausgeführt wird, selbst wenn eine Exception ausgelöst wird.

```python
try:
    result = 10 / 2
except ZeroDivisionError:
    print("Cannot divide by zero!")
else:
    print(f"Division successful! Result: {result}")
finally:
    print("This always executes — use it for cleanup tasks.")
```

## D. Assert-Anweisungen

### D1. `assert` verwenden, um `AssertionError` auszulösen

Die `assert`-Anweisung ist eine prägnante Möglichkeit, einen `AssertionError` auszulösen, wenn eine Bedingung nicht erfüllt ist. Sie wird häufig zur Validierung und zum Debuggen verwendet. Die Syntax lautet:

```python
assert boolean_expression, optional_message
```

Wenn Python eine `assert`-Anweisung auswertet:
- Wenn der Boolean-Ausdruck **`True`** ist, tut Python nichts und macht weiter.
- Wenn der Boolean-Ausdruck **`False`** ist, löst Python einen `AssertionError` mit der optionalen Meldung aus, falls eine angegeben wurde.

Das erste Beispiel unten läuft still durch, weil `1 == 1` `True` ist. Das zweite (auskommentierte) Beispiel würde einen `AssertionError` mit der Meldung `"That is not true"` auslösen, weil `1 == 2` `False` ist.

```python
assert 1 == 1
```

```python
#assert 1 == 2, "That is not true"
```

## E. Fazit

In dieser Demonstration haben Sie erkundet, wie Python Fehler kategorisiert und behandelt:

1. **Syntaxfehler** treten auf, wenn Python den Code nicht parsen kann, und führen immer dazu, dass das Programm scheitert, bevor die Ausführung beginnt.
2. **Exceptions** treten zur Laufzeit auf, wenn Python den Code versteht, aber während der Ausführung auf ein Problem stößt, etwa `ZeroDivisionError` oder `NameError`.
3. **`try`/`except`-Blöcke** erlauben es Ihnen, Exceptions abzufangen und alternatives Verhalten zu definieren, was Programmabstürze verhindert.
4. **Die `else`-Klausel** läuft nur, wenn im `try`-Block keine Exception auftritt, und hilft, normale Logik von der Fehlerbehandlung zu trennen.
5. **Die `finally`-Klausel** läuft immer, ob eine Exception auftrat oder nicht, und ist nützlich für Aufräumaufgaben.
6. **Bestimmte Exception-Typen** können in `except`-Klauseln gezielt angesprochen werden, und mehrere Typen können mit einem Tupel gemeinsam behandelt werden.
7. **`assert`-Anweisungen** bieten einen leichtgewichtigen Mechanismus, um einen `AssertionError` auszulösen, wenn eine Bedingung zu `False` ausgewertet wird, nützlich für Validierung und Tests.

# Demo – Cloud Computing 101

## Überblick

Diese Demonstration führt die grundlegenden Konzepte des Cloud Computing ein und erklärt, wie Databricks innerhalb einer cloudbasierten Umgebung funktioniert. Sie erkunden die Entwicklung vom lokalen und On-Premise-Computing hin zur Cloud-Infrastruktur, verstehen die Rolle von virtuellen Maschinen und Cloud-Speicher und sehen, wie Databricks Apache Spark für verteilte Verarbeitung und Unity Catalog für einheitliche Governance nutzt. Das Notebook schließt mit einer Einführung in Git und GitHub als Werkzeuge für Code-Versionierung und Zusammenarbeit ab.

## Lernziele

Am Ende dieser Demonstration können Sie:

1. **Lokales, On-Premise- und Cloud-Computing gegenüberstellen**, indem Sie die wesentlichen Unterschiede in Infrastruktur, Kosten und Skalierbarkeit beschreiben.
2. **Die Rolle von virtuellen Maschinen und Cloud-Speicher erklären** bei der Ermöglichung skalierbarer Mehrbenutzer-Datenverarbeitung.
3. **Beschreiben, wie Databricks Apache Spark verwendet** als seine verteilte Compute-Engine, einschließlich der Driver-Worker-Architektur und Serverless Compute.
4. **Das Governance-Modell von Unity Catalog zusammenfassen** und seinen dreistufigen Namensraum zum Organisieren und Absichern von Daten- und KI-Assets.
5. **Erklären, wie Git und GitHub Versionskontrolle und Zusammenarbeit unterstützen** in Daten- und Softwareprojekten, einschließlich der Integration mit Databricks Repos.

## A. Rechenumgebungen

### A1. Lokale Ausführung

Lokale Ausführung bezeichnet das Ausführen von Code nur mit den Compute-Ressourcen Ihrer eigenen Maschine – zum Beispiel ein Data Scientist, der Jupyter-Notebooks auf einem Laptop ausführt.

Dieser Ansatz ist einfach und erfordert keine externe Infrastruktur, ist aber durch den Speicher und die Rechenleistung eines einzelnen Geräts begrenzt. Er eignet sich am besten für kleine Datensätze und exploratives Arbeiten.

### A2. On-Premise-Computing

On-Premise-(On-Prem-)Computing bezeichnet eine Organisation, die ihr eigenes Cluster aus miteinander verbundenen Computern verwaltet, um Daten zu speichern und Code auszuführen. Dieses Modell bietet deutlich mehr Rechenleistung und Speicher als eine einzelne Maschine.

On-Prem-Infrastruktur bringt jedoch erheblichen Aufwand mit sich:

- Hohe Vorabkosten für Hardware
- Laufende Wartungs- und Betriebslast
- Begrenzte Fähigkeit, Kapazität schnell hoch- oder herunterzuskalieren

### A3. Cloud Computing

Cloud Computing adressiert die Einschränkungen der On-Prem-Infrastruktur, indem es Organisationen erlaubt, Speicher und Rechenleistung von großen Technologieunternehmen zu mieten – etwa Amazon (AWS), Microsoft (Azure) und Google (GCP).

In einem cloudbasierten Umfeld greifen Benutzer über einen Webbrowser oder eine Anwendung auf Daten und Compute zu. Die eigentlichen Daten und Berechnungen befinden sich in großen Lagerhallen voller Maschinen, genannt **Rechenzentren (Data Centers)**, die vollständig vom Cloud-Anbieter verwaltet werden.

Wesentliche Vorteile von Cloud Computing sind:

- **Geringere Kosten** – keine Notwendigkeit, physische Hardware zu kaufen oder zu warten
- **Elastische Skalierung** – nur den Speicher und das Compute bereitstellen, das Sie brauchen, und es freigeben, wenn Sie fertig sind
- **Zugänglichkeit** – von überall mit einer Internetverbindung auf Ressourcen zugreifen

> **Große Cloud-Anbieter**
>
> Databricks läuft auf allen drei großen Cloud-Plattformen: Amazon Web Services (AWS), Microsoft Azure und Google Cloud Platform (GCP). Die Wahl des Cloud-Anbieters Ihrer Organisation bestimmt, wo Ihre Daten- und Compute-Ressourcen gehostet werden.

## B. Grundlagen der Cloud-Infrastruktur

### B1. Virtuelle Maschinen

In einem cloudbasierten Umfeld läuft Code auf Computern, die von Cloud-Anbietern verwaltet werden. Der Zugriff auf diese Computer wird über **virtuelle Maschinen (VMs)** bereitgestellt.

Eine virtuelle Maschine ist eine softwarebasierte Abstraktion, die CPU, Speicher, Networking und Festplattenspeicher von anderen virtuellen Maschinen isoliert, die auf derselben physischen Hardware laufen. Diese Isolation bedeutet:

- Mehrere Benutzer können sich dieselbe physische Maschine teilen, ohne auf die Daten der anderen zuzugreifen
- Jede VM verhält sich wie ein unabhängiger Computer mit eigenem Betriebssystem und eigenen Ressourcen
- VMs können bei Bedarf erstellt, in der Größe angepasst und beendet werden

### B2. Cloud-Speicher

Cloud-Anbieter bieten spezialisierte Speicherdienste, die für Zuverlässigkeit, Beständigkeit und Skalierung ausgelegt sind. Einer der am weitesten verbreiteten Typen ist **Objektspeicher (Object Storage)**, der jede Art von Daten halten kann – Text, Bilder, Videos und Binärdateien.

| Anbieter | Objektspeicher-Dienst |
|---|---|
| AWS | Amazon S3 |
| Azure | Azure Data Lake Storage Gen2 (ADLS Gen2) |
| GCP | Google Cloud Storage (GCS) |

Zusätzlich zum Objektspeicher bieten Cloud-Anbieter verwaltete Dienste für relationale Datenbanken (MySQL, PostgreSQL, Microsoft SQL Server) und NoSQL-Datenbanken (Amazon DynamoDB, Azure Cosmos DB, Google Cloud Bigtable).

> **Databricks und Objektspeicher**
>
> Databricks liest aus und schreibt in Cloud-Objektspeicher (S3, ADLS Gen2 oder GCS) als seine primäre Datenschicht. Unity Catalog kann so konfiguriert werden, dass er den Zugriff auf Objekte in Ihren eigenen Speicherkonten direkt von der Databricks-Plattform aus verwaltet.

## C. Die Databricks Data Intelligence Platform

Da wir nun die Grundlagen der Cloud-Infrastruktur verstehen – virtuelle Maschinen, Objektspeicher und das Pay-as-you-go-Modell –, können wir sehen, wie Databricks auf diesen Primitiven aufbaut. Databricks bietet eine Data Intelligence Platform, die Data Engineering, Data Science, Machine Learning und Business Intelligence in einer einzigen kollaborativen Umgebung zusammenbringt. In diesem Abschnitt erkunden wir die Plattform selbst, die verteilte Compute-Engine, auf die sie sich stützt (Apache Spark), und die Governance-Schicht, die alle Daten- und KI-Assets absichert und organisiert (Unity Catalog).

### C1. Databricks-Überblick

Databricks bietet eine einheitliche, cloudbasierte Plattform für Datenanalyse, Business Intelligence, Data Science und Machine Learning. Sie läuft auf allen drei großen Cloud-Anbietern (AWS, Azure und GCP) und verarbeitet in Cloud-Objektspeicher gespeicherte Daten mit den virtuellen Maschinen dieses Cloud-Anbieters.

Databricks abstrahiert die Komplexität der Verwaltung verteilter Infrastruktur und erlaubt Datenteams, sich auf das Bauen und Ausführen von Datenpipelines, Modellen und Analysen zu konzentrieren, statt Cluster und Speichersysteme zu konfigurieren.

Wesentliche Fähigkeiten der Plattform sind:

- **Notebooks** – interaktive, mehrsprachige Dokumente (Python, SQL, Scala, R) für explorative Analyse und Entwicklung
- **Jobs** – geplante und orchestrierte Workflows für produktive Datenpipelines
- **SQL Warehouses** – serverlose Compute-Endpunkte, optimiert für BI-Queries und Dashboards
- **Machine Learning** – verwaltetes MLflow für Experiment-Tracking sowie Modelle und Feature Engineering in Unity Catalog
- **Unity Catalog** – zentralisierte Governance für Daten, KI-Modelle und Zugriffssteuerung

> **Lakehouse-Architektur**
>
> Databricks hat das **Lakehouse**-Paradigma begründet – es kombiniert den kostengünstigen, flexiblen Speicher eines Data Lake mit den Performance- und Zuverlässigkeitsgarantien eines Data Warehouse. Möglich wird dies durch Delta Lake, eine quelloffene Speicherschicht, die ACID-Transaktionen, Schema-Durchsetzung und Time Travel zu in Cloud-Objektspeicher gespeicherten Daten hinzufügt.

### C2. Apache Spark

Ein einzelner Computer hat typischerweise genug Speicher und Rechenleistung, um Datensätze bis zu einigen Gigabyte zu verarbeiten. Für größere „Big Data"-Workloads ist ein verteiltes Verarbeitungssystem erforderlich – eines, das einen großen Datensatz in kleinere Teilmengen namens **Partitionen** aufteilen und diese Partitionen gleichzeitig über mehrere Computer verarbeiten kann.

[Apache Spark](https://spark.apache.org/) ist eine quelloffene, verteilte Datenverarbeitungs-Engine, die diese Koordination automatisch verwaltet. Wenn Sie einen Spark-Job einreichen, tut Spark Folgendes:

1. Bestimmt, wie der Datensatz in Partitionen aufgeteilt wird
1. Weist die Partitionen den Computern im Cluster mit Verarbeitungsanweisungen zu
1. Sammelt die Ergebnisse pro Partition und berechnet die endgültige Ausgabe

Spark wurde als Forschungsprojekt an der University of California, Berkeley, entwickelt. 2013 wurde es an die Apache Software Foundation gespendet – und im selben Jahr gründeten seine Schöpfer Databricks. Databricks verwendet Apache Spark als seine zentrale Berechnungs-Engine und betreibt Spark-Cluster, die aus cloudbereitgestellten virtuellen Maschinen bestehen, um Daten in Cloud-Objektspeicher und anderen verbundenen Systemen zu verarbeiten.

#### Spark-Cluster-Architektur

Ein Spark-Cluster besteht aus zwei Arten von Knoten:

| Knotentyp | Rolle |
| --- | --- |
| **Driver** | Koordiniert den gesamten Job – plant die Ausführung, verteilt Aufgaben und sammelt Ergebnisse |
| **Workers** | Führen die eigentlichen Datenverarbeitungsaufgaben auf einzelnen Partitionen aus |

Wenn Sie ein Notebook an ein Cluster anhängen und Code ausführen, werden Ihre Anweisungen an den Driver gesendet, der die Workers orchestriert, um die Berechnung parallel durchzuführen.

> **Serverless Compute**
>
> Databricks bietet auch **Serverless Compute**, was die Notwendigkeit, Cluster zu konfigurieren oder zu verwalten, vollständig beseitigt. Mit Serverless stellt Databricks die zugrunde liegende Infrastruktur automatisch bereit und skaliert sie – Sie führen einfach Ihren Code aus und zahlen nur für die verbrauchten Ressourcen.

### C3. Unity Catalog

Unity Catalog ist die einheitliche Governance-Lösung für Daten- und KI-Assets auf der Databricks Data Intelligence Platform. Er bietet ein konsistentes und transparentes Sicherheitsmodell über alle unterstützten Cloud-Anbieter hinweg.

Unity Catalog unterstützt die folgenden Asset-Typen:

- **Strukturierte Daten** – Tabellen und Views
- **Unstrukturierte Daten** – Dateien und Ordner (über Volumes)
- **KI-Assets** – Modelle, Funktionen und andere ML-Artefakte

#### Dreistufiger Namensraum

Unity Catalog erweitert den traditionellen zweistufigen Namensraum (Schema + Tabelle) um eine zusätzliche Ebene und gibt Ihnen eine dreistufige Hierarchie:

| Ebene | Objekt | Beschreibung |
| --- | --- | --- |
| 1 | **Catalog** | Container auf oberster Ebene zum Organisieren von Datenassets (z. B. `production`, `development`) |
| 2 | **Schema (Datenbank)** | Gruppiert zusammengehörige Tabellen, Views und Funktionen (z. B. `sales`, `marketing`) |
| 3 | **Tabelle / View / Funktion** | Einzelne Daten- oder KI-Objekte (z. B. `customers`, `orders`) |

Um ein beliebiges Objekt zu referenzieren, verwenden Sie seinen voll qualifizierten Namen: `catalog.schema.object` – zum Beispiel `samples.tpch.orders`.

#### Governance-Funktionen

Unity Catalog bietet zentralisierte Zugriffssteuerung und Auditing:

- **Feingranulare Berechtigungen** – Zugriff auf Catalog-, Schema- oder einzelner Tabellenebene erteilen
- **Data Lineage** – verfolgt automatisch, wie Daten zwischen Tabellen und Notebooks fließen
- **Audit-Logging** – erfasst, wer wann auf welche Daten zugegriffen hat
- **Attributbasierte Zugriffssteuerung** – Sicherheitsrichtlinien auf Zeilen- und Spaltenebene

Die folgenden Zellen demonstrieren, wie man diese Hierarchie mit SQL erkundet.

> **Der `samples`-Catalog**
>
> Jeder Databricks-Workspace enthält einen schreibgeschützten `samples`-Catalog mit Beispieldatensätzen (wie TPC-H- und NYC-Taxi-Daten), die Sie zum Lernen und Experimentieren verwenden können, ohne Ihre eigenen Daten laden zu müssen.

```sql

```

```sql

```

```sql

```

## D. Code-Versionierung und Zusammenarbeit

### D1. Git und GitHub

[Git](https://git-scm.com/) ist ein freies und quelloffenes Versionskontrollsystem. Es verfolgt Änderungen an Code über die Zeit und erlaubt Ihnen:

- Frühere Versionen eines Projekts zu speichern und wiederherzustellen
- **Branches** zu erstellen, um neue Funktionen isoliert zu entwickeln
- Branches wieder zusammenzuführen (**Merge**), sobald Funktionen fertig sind

Git kann lokal auf Ihrer Maschine oder direkt innerhalb von Databricks ausgeführt werden. Sein Wert als Kollaborationswerkzeug wird verstärkt, wenn es mit [GitHub](https://github.com/) gepaart wird, einem cloudbasierten Hosting-Dienst für Git-Repositories. GitHub ermöglicht mehreren Mitwirkenden:

1. Ein geteiltes Repository in ihre eigene Umgebung zu klonen
1. Funktionen oder Korrekturen unabhängig zu entwickeln
1. Änderungen zurückzupushen und Pull Requests zur Überprüfung zu öffnen
1. Genehmigte Änderungen in die Haupt-Codebasis zu mergen

Die meisten Open-Source-Projekte – einschließlich Apache Spark – werden auf GitHub gehostet. Sie können Sparks vollständigen Quellcode ansehen, herunterladen und neue Funktionen in seinem [GitHub-Repository](https://github.com/apache/spark) beitragen.

> **Git in Databricks**
>
> Databricks integriert sich nativ mit Git-Anbietern (einschließlich GitHub, GitLab und Azure DevOps) über Databricks Repos und Git Folders. Das erlaubt Ihnen, Notebooks und Quelldateien direkt innerhalb des Databricks-Workspace zu versionieren.

## B. Überblick über Logging

Software mit Log-Meldungen zu instrumentieren ist eine grundlegende Best Practice für Debugging, Monitoring und betrieblichen Einblick.

In Databricks Apps haben Anwendungen die Möglichkeit, in Tabellen (Lakebase oder Lakehouse) oder auf externen Observability-Plattformen für die dauerhafte Aufbewahrung zu protokollieren. Wenn die Log-Ausgabe jedoch direkt im Tab **Logs** erscheinen soll, müssen diese Meldungen nach `stdout` oder `stderr` geschrieben werden.

In diesem Abschnitt erweitern wir den App-Code um eine schlanke Logging-Konfiguration, die Log-Meldungen während der Ausführung der App ausgibt.

Dieses Beispiel verwendet zwar das eingebaute Logging-Framework von Python, das übergeordnete Prinzip ist jedoch allgemeingültig: Anwendungen sollten bewusste Laufzeit-Telemetrie an einem Ort erzeugen, an dem Entwickler und Betreiber sie tatsächlich nutzen können.

### B1. Logging in Python

Das Logging-Framework von Python trennt drei Kernaufgaben:
- **Logger** – entscheidet, ob eine Meldung ausgegeben werden soll
- **Handler** – bestimmt, wohin die Meldung geht (stdout, stderr, Datei usw.)
- **Formatter** – steuert, wie die Meldung aussieht

Der Ablauf sieht so aus:

1. **Log-Aufruf** – `logger.warning(...)` mit Meldung und Level
2. **Logger** – Schwellenwertprüfung, z. B. `level = INFO`; `DEBUG` wird herausgefiltert
3. **Handler** – `StreamHandler` schreibt nach `stdout`
4. **Formatter** – ergänzt Zeitstempel, Namen und Level
5. Die Meldung erscheint im Databricks-Tab **Logs**

Die Python-Logging-Schwellenwerte sind wie folgt definiert:

| Level | Typische Verwendung | Beispiel |
| --- | --- | --- |
| `DEBUG` | Detaillierte Diagnose während Entwicklung oder Fehlersuche. | `logger.debug(...)` |
| `INFO` | Normale betriebliche Meilensteine oder erwartetes Verhalten. | `logger.info(...)` |
| `WARNING` | Unerwartete, aber behebbare Probleme. | `logger.warning(...)` |
| `ERROR` | Fehler, die eine Aufgabe oder Funktion beeinträchtigen. Exception samt Traceback aus einem Exception-Handler heraus. | `logger.error(...)` / `logger.exception(...)` |
| `CRITICAL` | Schwerwiegende Fehler, die die App-Stabilität gefährden. | `logger.critical(...)` |

### B2. Beispielcode

Hier ist ein allgemein empfohlenes Muster für die Einrichtung von Logging, das sich auch in einer Databricks App anwenden lässt.

```python
import sys
import logging

logger = logging.getLogger("app")
logger.setLevel(logging.INFO)
logger.propagate = False

if not logger.handlers:
    handler = logging.StreamHandler(sys.stdout)
    handler.setLevel(logging.INFO)
    handler.setFormatter(
        logging.Formatter("[%(asctime)s] [%(name)s] [%(levelname)s] %(message)s")
    )
    logger.addHandler(handler)

logger.info("initializing...")
```

Erläuterung der einzelnen Teile:

- **Importe** (Zeilen 1–2): Nötig, um auf die `logging`-API und die Definition von `stdout` zuzugreifen.
- **Logger instanziieren** (Zeile 4): Erstellt oder holt einen Logger namens `app`. Benannte Logger erleichtern es, Log-Meldungen von anderen Subsystemen (Bibliotheken, Plattform-Logs usw.) zu unterscheiden.
- **Logging-Schwellenwert** (Zeile 5): Legt die minimale Schwere fest, die dieser Logger ausgibt. Mit `INFO` werden alle informativen Meldungen, Warnungen und Fehler ausgegeben. Debug-Meldungen werden herausgefiltert.
- **Propagation deaktivieren** (Zeile 6): Verhindert, dass Meldungen an übergeordnete Logger (etwa den Root-Logger) weitergereicht werden. Das vermeidet doppelte Log-Ausgaben, falls in der Laufzeitumgebung bereits eine andere Logging-Konfiguration aktiv ist.
- **Handler einrichten** (Zeilen 8–14): Fügt einen Stream-Handler hinzu, der Log-Meldungen nach `stdout` schreibt, damit sie im Tab **Logs** von Databricks Apps erscheinen. Die Prüfung `if not logger.handlers` ist wichtig, um den Handler nicht mehrfach anzuhängen, falls dieser Code mehr als einmal ausgeführt wird – das würde zu doppelten Log-Meldungen führen. Hier könnten weitere Handler ergänzt werden, wenn Sie die Meldungen anderswo speichern möchten (z. B. in einer persistenten Datenbank).
- **Verwendung** (Zeile 16): Ein Beispiel, das eine informative Meldung ausgibt.
